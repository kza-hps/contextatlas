# VouchMe First Worked Example

VouchMe is the first customer-shaped example for ContextAtlas. It is not the ContextAtlas ontology.

The VouchMe example may use project language such as candidate, referee, recruiter, vouch, signal, and access request. Those terms belong in aliases, labels, classifications, and evidence. The stable coordinate remains generic:

```txt
CA:KZA:VOUCHME:N00042
```

## Why VouchMe Is Useful

VouchMe gives ContextAtlas a realistic proving ground because the same trust record may appear differently depending on actor, state, permission, and layer. A candidate, referee, recruiter, admin, developer, or AI agent may need related but different context.

That makes VouchMe useful for testing discovery, classification, route resolution, layer visibility, and coordinate context generation.

## Overlay Journey

The expected VouchMe experience is live-app first:

1. A user opens a VouchMe page.
2. A small Atlas Pin appears on the page without taking over the UI.
3. The pin shows the current coordinate, route, layer, label, and confidence.
4. The user pulls down the top blind to see `L0` product and user-journey meaning.
5. The user pulls up the bottom blind to see `L1`-`L5` implementation evidence.
6. The user can screenshot the visible overlay or copy the coordinate into ChatGPT, Claude, Codex, Cursor, or a support ticket.

The page itself remains the main visual surface. ContextAtlas adds a transparent topology HUD over the product instead of sending the user to a dashboard first.

## Atlas Pins

VouchMe pages can expose Atlas Pins or Waypoints without requiring users to understand the coordinate formula:

```txt
Atlas Pin
Coordinate: CA:KZA:VOUCHME:N00042
Alias: VM.J.CAN.040
Route: /vouches/[id]?view=candidate
Layer: L0
Label: Candidate receives completed Vouch ID
```

Another expected coordinate example:

```txt
Atlas Pin
Coordinate: CA:KZA:VOUCHME:N00050
Route: /candidate/vouch-id
Layer: L0
Label: Candidate receives reusable Vouch ID
```

Public users should see only the layer and label that are safe for them. Internal users, support, engineers, and AI agents can resolve the same coordinate into deeper layers when authorized.

## Atlas Blinds For VouchMe

Top blind pulled down:

- `L0` product meaning
- actor: candidate
- route: `/candidate/vouch-id` or `/vouches/[id]?view=candidate`
- journey position: receiving or reusing a Vouch ID
- label: `Candidate receives reusable Vouch ID` or `Candidate receives completed Vouch ID`
- coordinate: `CA:KZA:VOUCHME:N00050` or `CA:KZA:VOUCHME:N00042`

Bottom blind pulled up:

- `L1` route and page evidence
- `L2` workflow states and permissions
- `L3` Vouch ID records and related data model evidence
- `L4` integrations, platform services, deployment, and webhooks
- `L5` tests, prompts, UAT notes, agent instructions, and operational runbooks

When both blinds are collapsed, only tiny top and bottom pull tabs should remain visible.

## Layer Visibility

Shareable diagrams can be generated by layer:

- `L0`: public explanation, copy, and customer-safe journey narrative.
- `L1`: routes, pages, components, layouts, and UI entry points.
- `L2`: statuses, events, permissions, notifications, and business logic.
- `L3`: tables, records, storage, auth, policies, and data models.
- `L4`: APIs, platform services, webhooks, deployment, and infrastructure.
- `L5`: tests, prompts, UAT notes, agent instructions, optional context exports, and runbooks.

## Bootstrap Boundary

The current VouchMe atlas is a hypothetical first-customer example only. It should not be treated as verified production truth until discovery output and human review connect the coordinates to a real VouchMe repo or website.
